The catalogue

All 558 codes and names were parsed from the PDF and checked against the contents page, with no missing items across the 14 categories. The 558 embedded photos were extracted, mapped to codes by page and reading order (12 per page, 1:1), spot-checked against the printed names, and compressed to 300px WebP thumbnails at 9.6 KB each — 5.24 MB total. Only 60 render at a time, so the page opens on about 576 KB rather than the full 5.24 MB.

Commercial rules

Every plate R99, flat. Delivery R99 flat per order, anywhere in South Africa (confirmed 9 August 2026). Delivery 3–5 working days. One delivery fee per order, never two.

Sold plates stay visible under a semi-transparent SOLD banner and can still be added as pre-orders. Pre-order lines are priced but excluded from the payable total and listed separately in the WhatsApp message. A basket mixing in-stock and pre-order plates is held and shipped complete once the pre-order lands, so the single R99 covers it — the panel and the WhatsApp message both say so, and offer to split the order on request. A pre-order-only basket carries no delivery fee, because nothing ships.

Noted and overruled by decision: R99 courier on a R99 plate is a 100% uplift on a single-item order. If basket size becomes the problem, free delivery above a threshold lifts average order value without cutting the fee. The flat R99 stands unless revisited.

Running It & To-Do Listclub-chevelle.netlify.app

Order references

Format CHEV-YYMMDD-HHMM-XXX — date, time to the minute, then three random characters, e.g. CHEV-260816-1302-W7W.

The three characters exist because the reference is the only thing tying a payment back to an order: without them, two customers checking out in the same minute would share one. The alphabet omits B/8, I/1, O/0, S/5 and Z/2, so a reference read over the phone or typed into banking cannot come back as a different one.

Order capture

Every order is posted to the Netlify form orders as it is sent — reference, name, contact, address, total, shipping state and the full line items. They appear under Forms → orders in the Netlify dashboard, so a card payment can never arrive with nothing on record saying what it was for. Capture is fire-and-forget: if it fails the customer is never blocked, and the WhatsApp message still carries everything. The same reference is never posted twice.

Requires the Netlify project to be linked to the repository — Netlify detects the form at deploy time. Set captureOrders: false to switch it off.

Maintaining it

Everything editable sits in the BRAND object at the top of the script in site/index.html: name, legal entity, WhatsApp, price, delivery fee and time, the Yoco URL and trading name, PayShap and bank details, captureOrders, defaultStock, stock, the footnote, and soldOut.

  • Marking a plate sold — add its code to soldOut, e.g. soldOut: ["CC-CAR-014"]. The SOLD banner, pre-order tag, totals split, held-shipment note and WhatsApp message all follow automatically. Setting a code's stock to 0 does the same thing.
  • Stock levels — the basket is capped at what is on hand. defaultStock covers every code not listed in stock and is 3, the top of the range, so any plate you hold fewer of needs its own entry — stock: { "CC-CAR-014": 1 } — or the app accepts an order for three when you can ship one. Hitting the cap tells the customer why.
  • Removing the card button — clear yoco and the button, the card row and the card note all disappear.
  • The card note is derived, not hard-coded — if yocoName stops matching BRAND.name, the app reinstates the "the page shows X, which is us" disclaimer by itself, so a rename cannot leave stale reassurance on the page.
  • Republishing — commit to the repository and Netlify redeploys. URL unchanged. netlify.toml sets X-Frame-Options: DENY (this page shows banking details, so it must not be framable by a lookalike site), a CSP, Referrer-Policy, immutable caching for img/, and no-store for index.html.

Verification

test/_verify.mjs — 37 browser checks against the shipped site: reference format and uniqueness, the totals split, the disabled card button and withheld copy link on a pre-order-only basket, R198 + R99 = R297, the Yoco amount and reference matching the panel, the held-shipment copy, order capture end to end, the stock cap, the address requirement, and with Google Fonts blocked. test/_catalogue.mjs checks the files on disk instead of the running page: every code has a thumbnail and every thumbnail belongs to a code. Both run on every push and pull request, so the checks no longer depend on anyone remembering them.
